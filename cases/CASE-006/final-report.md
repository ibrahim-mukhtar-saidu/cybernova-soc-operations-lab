# CASE-006 — Final Investigation Report

## Executive Summary

CASE-006 investigated `ALERT-CASE-006-DET-WEB-001`, generated by `DET-WEB-001` after six suspicious web requests from source IP `203.0.113.50` against `lab-web-01`.

The activity contained multiple SQL injection indicators, including boolean-based testing, `UNION SELECT`, SQL comment markers, and the `sqlmap/1.8` user agent.

The alert was assessed as **High severity / High confidence**.

The evidence strongly supports classification as automated SQL injection probing. However, the available telemetry does **not** establish successful exploitation, unauthorized database access, data retrieval, or application compromise.

## Timeline Summary

The suspicious sequence began at `09:01:00Z`.

The source first submitted a boolean-style SQL injection probe against `/products`, followed by a `UNION SELECT` request.

Additional requests tested:

- `AND 1=1`
- `AND 1=2`
- `OR 1=1`

The activity subsequently targeted `/login`.

The first two suspicious requests returned HTTP 500 responses. The following four returned HTTP 200 responses.

The response codes alone do not establish successful exploitation.

## Investigation Findings

### Finding 1 — Detection Validity

The alert is valid.

The telemetry contains multiple independent SQL injection indicators and exceeds the configured suspicious-request and indicator thresholds.

### Finding 2 — Automated Tooling

All six suspicious requests used:

`sqlmap/1.8`

This materially increases confidence that the activity represents automated SQL injection testing.

User-agent values remain spoofable and should not independently establish attribution.

### Finding 3 — Multiple SQL Injection Techniques

The source used multiple techniques during a short sequence:

- boolean-based conditions;
- `UNION SELECT`;
- SQL comment markers.

This progression is consistent with structured SQL injection probing.

### Finding 4 — Exploitation Status

Successful exploitation is **not established**.

The available evidence does not include sufficient application-layer or database evidence to demonstrate unauthorized data access or modification.

Required validation would include:

- application logs;
- database audit logs;
- query execution evidence;
- response-body comparison;
- unauthorized record access;
- application state changes.

### Finding 5 — Scope

The observed activity is limited to the synthetic laboratory web host:

`lab-web-01`

There is no evidence in the supplied telemetry establishing:

- database compromise;
- credential theft;
- persistence;
- lateral movement;
- data exfiltration;
- additional compromised systems;
- attacker attribution.

## Threat Intelligence Assessment

The source IP `203.0.113.50` is a documentation/test address and is not treated as real-world malicious infrastructure.

The strongest intelligence signal is behavioral:

- repeated SQL injection probes;
- multiple techniques;
- automated tooling;
- targeted application parameters;
- multiple affected endpoints;
- server errors during initial probing.

The activity is analytically mapped to:

`T1190 — Exploit Public-Facing Application`

This mapping describes the observed behavior and does not prove successful exploitation.

## Hunting Results

Recommended hunting pivots include:

- source IP;
- user-agent;
- targeted paths;
- SQL injection patterns;
- URL and query parameters;
- HTTP response status;
- destination host.

Future hunting should also consider URL decoding, parameter normalization, source rotation, low-and-slow probing, WAF telemetry, and database audit correlation.

## Response Assessment

The appropriate response classification is:

**Suspicious SQL injection probing — validate and monitor.**

Recommended defensive actions include:

1. Preserve the original telemetry and alert.
2. Review application and web-server logs.
3. Correlate with database audit records.
4. Validate whether unauthorized access occurred.
5. Review application parameter handling.
6. Confirm use of parameterized queries.
7. Monitor for recurrence.

If exploitation were independently confirmed, containment and remediation should be escalated accordingly.

## Detection Improvement

The investigation identifies several opportunities for improving `DET-WEB-001`:

- normalize and URL-decode request parameters;
- detect encoded SQL injection patterns;
- correlate activity across applications;
- detect source-IP rotation;
- detect distributed low-and-slow probing;
- correlate with WAF telemetry;
- correlate suspicious web requests with database activity.

These improvements should be accompanied by regression tests to verify both detection and false-positive behavior.
