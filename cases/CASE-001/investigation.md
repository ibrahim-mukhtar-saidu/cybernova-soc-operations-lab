## 2. Investigation Objective

The objective of this investigation is to determine whether the authentication alert generated by DET-AUTH-001 represents suspicious activity requiring escalation.

The investigation focuses on:

1. Validating the alert against the underlying telemetry.
2. Establishing the exact sequence of authentication events.

The investigation does not assume malicious intent solely from the presence of repeated authentication failures.

## 5. Detection Logic Assessment

DET-AUTH-001 is configured to identify repeated failed SSH authentication attempts grouped by source IP and username.

Configured threshold:

**5 failed authentication attempts within 5 minutes**

Observed primary sequence:

**8 failed authentication attempts within the configured window**

Therefore, the observed activity exceeded the detection threshold.

The detection also escalates the severity when successful SSH authentication is observed from the same source IP and username after the failure sequence.

In CASE-001:

- Eight failed attempts were observed.
- The failures targeted `root`.
- The source IP remained `198.51.100.25`.
- A successful SSH authentication was subsequently observed.
- The successful authentication was recorded as `EVT-001012`.

### Detection Assessment

**Detection logic correctly triggered.**

The detection behavior is consistent with its documented configuration.

## 8. Analyst Interpretation

The authentication sequence is suspicious because it combines:

- repeated failed authentication attempts,
- a privileged target account,
- a consistent source IP,
- SSH as the access protocol,
- and successful authentication following the repeated failures.

This combination increases the priority of the investigation.

The activity is consistent with a possible brute-force authentication attempt followed by successful credential use.

However, this interpretation remains an analyst assessment rather than direct proof of malicious activity.

The available evidence does not establish:

- who controlled the source IP,
- whether the login was authorized,
- whether credentials were compromised,
- whether the successful session performed malicious actions,
- whether persistence was established,
- whether the host was compromised,
- or whether any data was accessed or modified.

## 9. Investigation Hypotheses

### Hypothesis H1 — Unauthorized Brute-Force Followed by Successful Access

An unauthorized actor repeatedly attempted authentication against the `root` account and eventually obtained valid credentials.

**Supporting evidence:**

- Eight failed SSH authentication attempts.
- Same source IP across the sequence.
- Same privileged account targeted.
- Successful authentication after the failures.

**Evidence required for confirmation:**

- SSH session records.
- Process execution telemetry.
- Command history or equivalent authorized endpoint evidence.
- Account and privilege activity.
- Network activity following `EVT-001012`.
- Host-level forensic evidence.

**Current assessment:** Plausible but not confirmed.

---

### Hypothesis H2 — Authorized User or Administrator With Authentication Errors

An authorized administrator repeatedly entered incorrect credentials and subsequently authenticated successfully.

**Supporting evidence:**

- Successful authentication may be legitimate.
- Authentication failures can occur because of forgotten or incorrectly entered credentials.
- Laboratory telemetry does not identify the operator.

**Evidence required for confirmation:**

- Authorized activity records.
- Expected administrator source information.
- Change or maintenance records.
- Identity-management evidence.

**Current assessment:** Possible.

---

### Hypothesis H3 — Automated or Misconfigured Authentication Client

An automated process repeatedly attempted authentication using outdated or incorrect credentials before eventually succeeding.

**Supporting evidence:**

- Repeated authentication attempts can originate from automated systems.
- Authentication telemetry alone does not identify the originating process.

**Evidence required for confirmation:**

- Endpoint process telemetry.
- Application or service configuration.
- Scheduled task information.
- Automation or infrastructure logs.

**Current assessment:** Possible.
