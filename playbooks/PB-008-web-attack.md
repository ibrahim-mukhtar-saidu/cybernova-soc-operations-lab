# PB-008 — Web Attack

## 1. Purpose

PB-008 provides a structured Security Operations Center (SOC) investigation and response workflow for suspicious web attack activity detected by `DET-WEB-001`.

The playbook is designed around suspicious SQL injection activity observed in the CYBERNOVA SOC laboratory.

It provides analysts with a repeatable workflow for:

* alert validation;
* evidence classification;
* web-request analysis;
* source-IP attribution;
* host attribution;
* targeted-path analysis;
* SQL injection indicator validation;
* risk-score interpretation;
* application-layer correlation;
* server-log correlation;
* timeline reconstruction;
* indicator extraction;
* threat-intelligence review;
* MITRE ATT&CK mapping;
* false-positive assessment;
* severity assessment;
* containment;
* eradication;
* recovery;
* post-recovery monitoring;
* threat hunting;
* detection validation;
* adversarial review;
* detection-engineering feedback;
* escalation;
* closure;
* evidence packaging.

The playbook does not automatically classify an application as compromised.

Observed SQL injection indicators represent evidence requiring investigation and validation.

## 4. Detection Trigger

`DET-WEB-001` evaluates web request events.

The detector groups web requests by:

```text
source_ip + host
```

Requests are then ordered chronologically.

A five-minute detection window is evaluated.

The detector requires:

```text
minimum suspicious requests = 4
minimum distinct indicators = 2
```

The calculated risk score must reach:

```text
70 or higher
```

before an alert is generated.

---

## 5. Detection Logic Summary

The detection pipeline is:

```text
Web request telemetry
        |
        v
Web request filtering
        |
        v
Group by source IP + host
        |
        v
Chronological ordering
        |
        v
Five-minute correlation window
        |
        v
SQL injection indicator extraction
        |
        v
Minimum suspicious-request check
        |
        v
Distinct-indicator check
        |
        v
Risk scoring
        |
        v
Risk threshold >= 70
        |
        v
DET-WEB-001 alert
```

The detector is therefore a behavioral correlation rule rather than a single-string signature.

## 6. Detection Thresholds

Current implementation constants:

```text
WEB_001_MIN_SUSPICIOUS_REQUESTS = 4
WEB_001_WINDOW_MINUTES = 5
WEB_001_MIN_INDICATORS = 2
```

The playbook must use these values as the authoritative laboratory configuration unless the detection implementation is deliberately changed.

---

## 7. Risk Scoring

The detector begins with:

```text
20
```

Risk scoring can increase according to observed evidence.

Additional scoring includes:

```text
+20 when minimum suspicious-request threshold is reached
+25 when minimum distinct-indicator threshold is reached
+20 for sqlmap_user_agent
+15 for sql_union_select
+10 for sql_boolean_test
+10 when any suspicious request returns HTTP 500 or greater
```

The final score is capped at:

```text
100
```

The detector only generates the alert when:

```text
risk_score >= 70
```

Risk score is a prioritization mechanism.

It is not proof of exploitation.

## 57. Adversarial Review

The detection must be evaluated against controlled evasion scenarios.

### Source-IP rotation

Attackers may rotate source addresses.

Limitation:

```text
grouping is based on source_ip + host
```

Improvement:

* broader correlation;
* authenticated-session correlation;
* infrastructure enrichment.

### Slow attacks

Attackers may distribute requests over longer periods.

Limitation:

```text
five-minute window
```

Improvement:

* longer-term behavioral correlation.

### Request encoding

Attackers may encode SQL syntax.

Limitation:

* raw indicator matching may miss normalized variants.

Improvement:

* controlled canonicalization and decoding.

### User-agent variation

Attackers may change automated-tool user-agents.

Limitation:

* `sqlmap_user_agent` becomes less useful.

Improvement:

* behavioral request analysis.
