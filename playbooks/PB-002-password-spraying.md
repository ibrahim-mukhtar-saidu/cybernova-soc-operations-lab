# PB-002 — Password Spraying Authentication

## 1. Purpose

This playbook provides a repeatable analyst workflow for investigating password-spraying authentication alerts within the CYBERNOVA SOC Operations Laboratory.

The playbook is designed around detection `DET-AUTH-002` and the corresponding `CASE-002` password-spraying investigation workflow.

The objective is to help an analyst:

* Validate the alert.
* Confirm the observed authentication pattern.
* Identify affected users and source infrastructure.
* Establish the relevant investigation timeline.
* Preserve supporting evidence.
* Distinguish password spraying from legitimate authentication activity.
* Investigate whether successful authentication occurred after the detected activity.
* Assess related account, host, and authentication activity.
* Perform controlled threat-intelligence enrichment where appropriate.
* Determine whether additional containment or escalation would be warranted in an authorized environment.
* Feed investigation findings back into detection engineering.

This playbook is written for a synthetic SOC laboratory and does not represent production SOC operational experience.

---

## 2. Scope

This playbook covers authentication telemetry associated with password-spraying behavior.

Primary detection:

```text
DET-AUTH-002
Password Spraying Authentication Detection
```

Primary investigation:

```text
CASE-002
Password Spraying
```

The workflow focuses on situations where authentication failures are distributed across multiple user accounts within a defined detection window.

The playbook may also be used when related authentication alerts provide evidence of successful authentication, privileged activity, account compromise indicators, or additional attack stages.

---

## 3. Trigger

Begin this playbook when `DET-AUTH-002` generates an alert indicating that the configured password-spraying conditions have been met.

The current laboratory detection requires:

* At least 6 authentication failures.
* At least 6 distinct targeted users.
* Activity occurring within the configured 5-minute detection window.
* Authentication telemetry satisfying the detector's required schema and validation rules.

The detection threshold is an analytical trigger rather than proof of malicious activity.

Legitimate environments may produce similar patterns through:

* Misconfigured applications.
* Expired passwords.
* Service-account failures.
* Authentication synchronization problems.
* Administrative testing.
* Automated software using stale credentials.
* Legitimate user behavior.

The alert therefore requires analyst validation.

---

## 4. Severity Guidance

The initial severity should follow the detection output and available contextual evidence.

A password-spraying alert should receive increased investigative priority when one or more of the following are observed:

* A successful authentication follows the failed attempts.
* A privileged account is targeted successfully.
* Multiple accounts authenticate from the same suspicious source.
* Authentication is followed by unusual session activity.
* Authentication is followed by privilege-related commands.
* Authentication is followed by persistence activity.
* Authentication is followed by suspicious network activity.
* Authentication is associated with malware execution.
* Multiple hosts are affected.
* The activity continues beyond the initial detection window.

Severity should not be increased solely because an alert exists.

## 6. Alert Authenticity and Data Quality

Verify that:

1. The supporting telemetry exists.
2. Event IDs referenced by the alert can be traced back to source telemetry.
3. Timestamps contain valid values.
4. Authentication events belong to the same detection window.
5. Targeted users are genuinely distinct.

10. No malformed or duplicated telemetry distorted the detection.

## 7. Triage

Determine:

### 7.1 What happened?

Establish:

* Number of authentication failures.
* Number of distinct targeted users.
* Source IP or source infrastructure.
* Target host or hosts.
* Authentication protocol.
* First observed event.
* Last observed event.
* Whether the activity was concentrated within the detection window.
* Whether any authentication succeeded.

### 7.2 Why is it suspicious?

Password spraying differs from traditional brute-force activity because attempts are distributed across multiple accounts rather than repeatedly targeting one account.

The analyst should determine whether the observed distribution is consistent with:

* A common password-spraying pattern.
* Legitimate automated activity.
* Administrative testing.
* Application malfunction.
* Another authentication anomaly.

### 7.3 What happened immediately afterward?

Search for:

* Successful authentication.
* Session creation.
* Privileged activity.
* Command execution.
* Account changes.
* Persistence.
* Network connections.
* File modifications.
* Additional authentication attempts.

## 8. Authentication Investigation

Review all authentication events associated with the detection.

Document:

* Source IP.
* Destination host.
* Target users.
* Authentication protocol.
* Authentication result.
* Timestamp.
* Failure reason where available.
* Session identifier where available.
* Supporting event IDs.

Construct the authentication sequence chronologically.

Example analytical structure:

```text
Multiple failed authentication attempts
        ↓
Distributed targeting across users
        ↓
Detection threshold reached
        ↓
Alert generated
        ↓
Search for successful authentication
        ↓
Search for post-authentication activity
```

The sequence should be supported by telemetry rather than inferred solely from the alert.

---

## 9. Distinct-User Analysis

Password spraying depends heavily on distributed account targeting.

Calculate or validate:

```text
distinct targeted users
```

Confirm that the detector's distinct-user requirement was genuinely satisfied.

Review:

* Usernames.
* Number of attempts per user.
* Ordering of targeted accounts.
* Whether privileged accounts were targeted.
* Whether service accounts were targeted.
* Whether disabled or nonexistent accounts were targeted.

A large number of distinct accounts does not independently establish malicious intent.

---

## 10. Source-IP Investigation

Use the source IP as a primary investigation pivot.

Search for:

* Earlier authentication activity.
* Later authentication activity.
* Activity against additional hosts.
* Other targeted users.
* Successful authentications.
* Related network telemetry.
* Existing alerts.
* Previous laboratory cases.

Determine whether the source IP is:

* Internal.
* External.
* Synthetic laboratory infrastructure.
* Associated with expected administrative activity.
* Unknown.

For this laboratory, documentation must clearly distinguish synthetic addresses from real-world reputation claims.

---

## 11. Account Investigation

For each affected account, determine:

* Whether the account is privileged.
* Whether authentication succeeded.
* Whether the account was active before the event.
* Whether additional authentication activity occurred.
* Whether the account was subsequently used for suspicious activity.
* Whether account changes occurred.
* Whether the same account appears in other alerts.

Prioritize accounts that show:

```text
password-spraying failures
        +
successful authentication
        +
unusual post-authentication activity
```

This combination should receive greater investigative attention than isolated authentication failures.

---

## 12. Successful Authentication Review

Search immediately after the password-spraying window for successful authentication events.

Record:

* User.
* Host.
* Source IP.
* Timestamp.
* Authentication protocol.
* Session ID.
* Supporting event ID.

A successful authentication following password spraying is important evidence, but it does not automatically establish account compromise.

The analyst should investigate what occurred after the successful authentication.

## 14. Related Authentication Activity

Search for authentication behavior before and after the alert.

Look for:

* Repeated spraying attempts.
* Brute-force activity against individual accounts.
* Authentication against multiple hosts.
* Multiple source IPs.
* Multiple protocols.
* Successful authentication after failures.
* Additional targeted accounts.

Pay particular attention to activity that crosses the original detection window.

The detection window is a detection boundary, not necessarily the complete attack duration.

## 19. MITRE ATT&CK Context

Password spraying is associated with:

```text
T1110 — Brute Force
T1110.003 — Password Spraying
```

The ATT&CK mapping describes the behavior represented by the detection.

It does not independently prove that a real-world adversary performed the activity.

Additional techniques should only be recorded when supported by observed telemetry.

For example:

```text
T1078 — Valid Accounts
```

may become relevant if successful authentication is observed and the investigation establishes that the account was used as a valid credential.

## 20. False-Positive Review

Consider legitimate explanations including:

* Enterprise authentication testing.
* Application configuration errors.
* Password expiration.
* Automated systems using stale credentials.
* Administrative account testing.
* Identity-management synchronization problems.
* Service-account failures.
* User behavior involving repeated login attempts.

Ask:

1. Is the source expected?
2. Are the targeted accounts expected?
3. Is the timing expected?
4. Is the destination host expected?
5. Is the authentication protocol expected?
6. Did successful authentication occur?
7. Did suspicious activity follow?

Do not close an alert as benign solely because a legitimate explanation is possible.

Record the evidence supporting the final assessment.

## 21. Containment Decision

Containment actions should only be considered within an authorized environment.

Potential response options may include:

* Blocking or restricting a confirmed malicious source.
* Temporarily restricting an affected account.
* Requiring credential reset.
* Terminating an unauthorized session.
* Isolating an affected host.
* Increasing authentication monitoring.

The laboratory does not perform destructive or production containment.

For portfolio evidence, document containment as:

```text
Recommended response action
```

unless an authorized laboratory exercise actually executed it.

## 25. Adversarial Detection Review

Consider how an attacker or noisy system might evade the detector.

### Scenario 1 — Slow spraying

Spread authentication attempts beyond the configured window.

Potential limitation:

```text
Activity distributed over a longer period may not satisfy
the configured detection window.
```

Improvement:

```text
Add complementary longer-window analytics where justified.
```

### Scenario 2 — Multiple source IPs

Distribute attempts across several source addresses.

Potential limitation:

```text
Source-based grouping may fragment activity.
```

Improvement:

```text
Correlate additional identity, host, ASN, device, or infrastructure
signals where reliable telemetry exists.
```

### Scenario 3 — Fewer targeted accounts

Keep the number of distinct users below the threshold.

Potential limitation:

```text
The detector may intentionally avoid low-volume activity.
```

Improvement:

```text
Use complementary low-volume authentication analytics.
```

### Scenario 4 — Duplicate telemetry

Send duplicate events to distort counts.

Potential limitation:

```text
Poor event uniqueness can inflate observed activity.
```

Improvement:

```text
Maintain event identifiers and deterministic deduplication controls.
```

### Scenario 5 — Timestamp manipulation

Alter event timestamps.

Potential limitation:

```text
Timeline reconstruction may become unreliable.
```

Improvement:

```text
Validate timestamps and preserve trusted collection-time metadata
where available.
```

## 26. Escalation Criteria

Escalate the investigation when evidence indicates:

* Successful authentication following spraying.
* Privileged account access.
* Suspicious post-authentication activity.
* Persistence.
* Malware execution.
* Suspicious network activity.
* File-integrity violations.
* Multiple affected hosts.
* Multiple related detections.
* Continued activity beyond the original window.
* Insufficient evidence to safely close the case.

For a multi-stage sequence, consider escalation when multiple independent detections share reliable investigation pivots.

---

## 27. Closure Criteria

The investigation may be closed when:

* Alert validity has been established.
* Supporting evidence has been preserved.
* The authentication timeline is complete enough for the available telemetry.
* Affected users and hosts have been reviewed.
* Successful authentication was investigated.
* Related detections were considered.
* False-positive reasoning was documented.
* Threat-intelligence boundaries were recorded.
* ATT&CK context was documented.
* Response considerations were addressed.
* Detection limitations were identified.
* Required artifacts are complete.
* The final analyst assessment is supported by evidence.

Do not close solely because no compromise was proven.

A correct disposition may be:

```text
Suspicious activity observed; compromise not established.
```

when the evidence supports that conclusion.

## 31. Analyst Conclusion

A password-spraying alert represents a distributed authentication pattern that requires contextual investigation.

The analyst should establish:

```text
What was observed?
        ↓
Why did DET-AUTH-002 trigger?
        ↓
Which accounts and hosts were targeted?
        ↓
Did authentication succeed?
        ↓
What happened after authentication?
        ↓
Were related detections triggered?
        ↓
What evidence supports the assessment?
        ↓
What response is justified?
        ↓
What should detection engineering improve?
```

The investigation must preserve the distinction between:

```text
Observed evidence
```

and:

```text
Analyst interpretation
```

A password-spraying alert alone does not prove account compromise.

Strong SOC analysis requires evidence correlation, timeline reconstruction, false-positive consideration, adversarial testing, response planning, and detection-engineering feedback.
